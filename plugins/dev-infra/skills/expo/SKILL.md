# Module: expo

Steps run with `${CLAUDE_PLUGIN_ROOT}/skills/bootstrap/references/step-protocol.md`.
Config conventions: `${CLAUDE_PLUGIN_ROOT}/skills/environments/references/expo-eas.md`.

**Requires:** project-repo

## Decisions

- **Expo owner** — personal account or an Expo organization (recommended if others may join later).
- **Firebase SDK flavor** — JS SDK (works in Expo Go; enough for Auth, Functions, Firestore) or
  `@react-native-firebase` (native: Analytics, Crashlytics, push via FCM; needs dev-client builds).
  This is an app-architecture choice, so **deferring it is a valid answer**: infra provides config for
  both (EAS env vars now; per-env `GoogleService-Info.plist` via `firebase apps:sdkconfig IOS <appId> -P <env>`
  when the native SDK is chosen, wired through `ios.googleServicesFile` in app.config.ts by `APP_VARIANT`).
  The demo always uses the JS SDK in its own file.

## Steps

1. **EAS CLI** — Check: `eas --version` (no "new version available" notice). Configure: `npm i -g eas-cli@latest`.
2. **Expo account** — Check: `eas whoami`. User: sign up at https://expo.dev/signup (free), then `eas login` in a separate terminal.
   Record: `apps.mobile.expo_owner`.
3. **App** — Check: `apps/mobile/package.json`.
   Configure (confirm): `pnpm create expo-app apps/mobile --template default --no-install --yes`, then
   `pnpm install` from the repo root and `npx expo-doctor` in the app.
   The template also writes `AGENTS.md` (follow it: use versioned Expo docs, `npx expo install`) and
   `apps/mobile/.claude/settings.json` enabling `expo@claude-plugins-official` — tell the user; offer to move
   it to the root `.claude/settings.json` so it applies when Claude runs from the repo root.
   Set in app.json: `name`, `slug` (= project slug), `scheme`, `owner` (= expo_owner).
4. **EAS project** — Check: app config has `extra.eas.projectId`.
   Configure: `eas init --non-interactive --force` (works when logged in and `owner` is set; writes projectId to app.json).
5. **Variants + profiles** — `app.config.ts` (extends app.json; bundle id/name by `APP_VARIANT`;
   `ios.appleTeamId` if known) and `eas.json` (`development` with `developmentClient` → requires
   `npx expo install expo-dev-client`; `development-simulator` extends it with `ios.simulator: true`;
   one profile per further environment). See the `environments` skill references.
   Check: `APP_VARIANT=<v> npx expo config --type public --json` shows the expected name + bundle id per variant.
6. **EAS environment variables** (if `firebase` enabled) — Check: `eas env:list --environment <eas_environment> --format short`.
   Configure, per environment: web app config from `firebase apps:sdkconfig WEB <appId> -P <id> --json` →
   `EXPO_PUBLIC_FIREBASE_{API_KEY,AUTH_DOMAIN,PROJECT_ID,STORAGE_BUCKET,MESSAGING_SENDER_ID,APP_ID}`,
   `EXPO_PUBLIC_FIREBASE_FUNCTIONS_REGION`, `EXPO_PUBLIC_APP_ENV`, each with
   `eas env:create --environment <e> --name <N> --value <V> --visibility plaintext --scope project --non-interactive --force </dev/null`
   (**`</dev/null` matters**: `eas` reads stdin and swallows the rest of a `while read` loop).
   Local dev: `eas env:pull --environment development` → `.env.local` (must be gitignored).
7. **Lint** — the template's `lint` script (`expo lint`) installs ESLint interactively on first run and fails in CI.
   Configure: `npx expo install eslint eslint-config-expo -- --save-dev` + `eslint.config.js` using
   `eslint-config-expo/flat` (ignore `dist/*`, `.expo/*`, `expo-env.d.ts`). Fix template lint errors properly.
8. **Typecheck in CI** — `expo-env.d.ts` (CSS module types etc.) is generated by `expo start` and gitignored,
   so add a `pretypecheck` script that writes `/// <reference types="expo/types" />` to it.

## Done when

`pnpm --filter mobile typecheck` passes from a clean checkout; `npx expo-doctor` passes; Metro boots and the
iOS manifest (`curl -H 'expo-platform: ios' http://localhost:<port>/`) shows the dev variant name + bundle id.
